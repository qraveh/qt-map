# V&V report — the Map table and map bar, baseline 8106b9e (edition 2026.09 beta)
QT-Map · SP01 · build/audit/vv · session C1, 16 Sep 2026 · deterministic suites complete (final counts below and in `SUMMARY.md`); the random suite is partial.

## Method (SPEC_machines-on-the-map §4, as executed)
1. **Independent oracle** (`oracle.py`, `RULES.md`): written from the editor's written lit-set rules and `data/graph.json` only, without reading `map_js.py`. 14 lenses mapped to node attributes; 17 points the written rules leave open are listed in RULES.md §Ambiguities; 7 sanity tests (`test_oracle.py`) pass.
2. **Driver** (`driver.py`, `DRIVER.md`): Playwright over the built page; a station is lit iff its `g.station` lacks class `dim`; lines by `path.pathline`; edges from the D3 datum (type names `requires`, `replaces`, `conflicts` — the written rules say "alternatives"; the page says "replaces"). Every control is driven through its real DOM element.
3. **Differential runs** (`runner.py`): suites `single` (every lens × value, each toggle, each isolation, each station focus — 194 states), `pairs` (3,357 pairs across dimensions incl. the 8 toggle combinations × 14 isolations × marks values), `multi` (1,358 Ctrl-multi-select sets of size 2–3 per lens, toggles off/all-on), `metamorphic` (200 seeded cases of the four relations), `static` (6 checks), `random` (sequences of 10–40 actions with invariants after every step — 50 of the SPEC's 5,000 run so far; resumable).
4. **Adjudication** (RULES.md §Adjudications): the first differential pass showed 8 signatures; each was decided against the written rule — 3 oracle fixes, 4 design gaps (page behaviour recorded as the de-facto rule, flagged for the editor), 1 driver/page split (click interception).

## Defects found on the baseline (to fix in C2 before adding features, then re-run)
1. **`f` lens (error family) reads only the first value of a station's `f` list** — `build/map_js.py:146`. Effect: "burst" has no button (unreachable value → 8 + 14 + 2 cases of `unmappable-value`); every other value misses the stations that carry it in a later position: bias misses `cavity`, `g_bos`; coherent misses 9 (`alkali`, `enc_eo`, `fluxonium`, `fluxq`, `g_elec`, `g_mwspin`, `g_ryd`, `ic_cryolink`, `transmon`); pauli misses 10; leak 8; loss 4; erasure `dec_corr`; gauss `code_bosonic`. Minimal repro: reset → lens f → value "coherent" → 28 lit, expected 37. The legend total for f/pauli is off for the same reason.
2. **Clicks intercepted at ≤ 1024 px** — the fixed `#insp` panel (`build/page_css.py:437`) and the sticky `#mobilebar` (`:393`) cover stations and controls; 7 of 14 random sequences hit a click timeout at 1024/600/400 px. A user cannot click those stations at those widths.
3. **Legend totals** — static by design except the reading-marks keys (RULES.md §Adjudications 6); one f-family total is wrong because of defect 1 (folded into 1).
4. **Isolate → clear with a station focused is not the identity** (metamorphic M2, 44 cases, all with a focus): after clearing the isolation the page draws relation edges across the whole graph instead of re-narrowing them to the focused station's lit set — the focus term is not re-applied on clear. Repro: reset → click `g_bos` (toggle requires on) → isolate `sc` → clear isolation → compare edges. Probable state leak in the isolate-clear handler; to confirm by hand in C2.

## Design gaps recorded for the editor (RULES.md §Adjudications 1, 2, 4, 6)
Lines are hidden under any non-family lens unless something is isolated or focused; isolate/focus decide the lines and a family value only narrows them; the time lens bins values to 7 centres with ties to the faster bin; legend totals are static except the reading-marks keys. The oracle follows the page on these four; a written rule from the editor would let the next run test them as requirements.
